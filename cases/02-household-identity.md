# 案例 02：不同年份的户号不能直接关联

## 真实证据

- 2011 年包内样本和 2014 年文件的 LCLid 为 MAC 字符串或字符串字典类型。
- 2012 年文件的 LCLid 为 int64，开头样本为 0。
- 本次源文件清单和压缩包未提供这两类户号之间的映射。

导入后原始户号组有 5,229 个户号；2012 年独立组有 5,552 个编码。它们可能对应重叠家庭，不能相加当作独立家庭总数，也不能假设编号 0 就是 MAC000000 或第一个 MAC 户。

## 会造成什么影响

错误的身份关联会把不同家庭的时间序列接在一起，或把同一家庭拆成多个对象，进而影响跨年统计、训练测试隔离和户级预测。当前证据支持“映射未知”，不支持“确定是不同家庭”。

## 工具如何处理

`identity.cross_file` 输出每个文件的字段类型与前五个样本。混合数值/文本表示在未提供映射时阻断跨文件身份关联；类型相同仍标记 `unknown`，不作身份认证。

本版检查器不支持验证外部映射表，不能通过简单添加文件让它自动转为通过。取得映射后，仍需要检查来源版本、唯一性、覆盖率以及是否一对一。

现有导入器要求数值户号显式设置 `--encoded-id-prefix`，本次使用 `encoded2012_`。该前缀仅防止误合并，不恢复真实身份。

## 最小复现与验收

```bash
.venv/bin/python scripts/reproduce_trust_cases.py
.venv/bin/oed check cases/reproduced/text-ids.feather cases/reproduced/numeric-ids.feather -o cases/reproduced/manual-identities
```

合成文件分别使用 `MAC000001` 和 0，时间与读数相同，但不能凭这些特征断言同一家庭。

验收：跨文件身份关联为 `fail`，证据同时显示 text 与 numeric；单独检查文本文件时身份仍为 `unknown`。CLI 的失败是针对所请求的身份关联，不禁止单文件内分析。

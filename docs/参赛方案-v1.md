## 1. 项目定义

**一句话**：为双碳时代打造的开源能耗时序数据基座——一套中文优先的**统一数据规格**、覆盖全球主流公开数据集的**转换器集**、LLM 驱动的**智能质量评注管线**、开箱即用的**基准评测**，四位一体的数据基础设施。

**痛点**：全球公开能耗/负荷数据集（REDD、UK-DALE、REFIT、ECO、IDEAL、LCL……）格式碎片化严重——HDF5/CSV/Excel 各异、采样率不一（1s~15min）、单位混乱（kW/W/ kWh 混用）、元数据缺失、质量参差。研究者每接入一个新数据集都要重写解析与预处理；中文生态没有统一规格与质量标准。这正重复着自动驾驶数据集被 OpenDriveData（CCF 开源创新大赛一等奖）解决之前的混乱。

**定位**：赛道一"数据平台 + AI 工具链"的交叉——不是又一个分析库，而是**领域数据标准 + 质量基础设施 + 基准**。

**参赛主体（P0 硬门槛）**：大赛不接受个人报名，在校生走"学生团队"，已工作走企业/开源社区联合申报。**10/16 前完成官网报名提交。**

## 3. 系统架构

```
数据源(7+)                  规格核心                     增值层
┌──────────┐   ┌─────────────────────────┐   ┌──────────────────────┐
│ REDD     │──▶│  oed-schema (JSON Schema)│──▶│ 确定性质量扫描引擎     │
│ UK-DALE  │   │  · Parquet 主存储         │   │ (缺口/漂移/单位/时区)  │
│ REFIT    │   │  · 元数据 sidecar (JSON)  │   └──────────┬───────────┘
│ ECO      │   │  · 质量标记词汇表          │   ┌──────────▼───────────┐
│ IDEAL    │   │  · 数据血缘记录           │   │ LLM 智能评注管线       │
│ LCL      │   └─────────────────────────┘   │ schema+统计→规则生成    │
│ 自有能耗  │            │                    │ →执行→解释→报告卡      │
│ 数据集   │            ▼                    │ (人工确认环节)         │
└──────────┘   ┌─────────────────────────┐   └──────────┬───────────┘
   converters/ │  oed CLI (typer)         │◀────────────┘
   一数据集一包 │  convert/scan/rule/      │   ┌──────────────────────┐
               │  report/bench 子命令      │──▶│ 基准评测 benchmark/    │
               │  + Streamlit 报告 UI      │   │ 负荷预测/NILM 排行榜   │
               └─────────────────────────┘   └──────────────────────┘
```

**演示主线（demo 视频的 90 秒）**：`oed convert redd` 一键标准化 → `oed scan` 发现单位异常与缺口 → `oed rule --ai` 生成领域规则（"热水器 >12kW 判异常"）并解释 → `oed report` 出质量报告卡 → `oed bench` 出预测/NILM 基准表。

### 3.1 对标与借鉴（获奖蓝本 + 开源对标）

- **获奖蓝本 OpenDriveData**（中科院软件所，CCF 开源创新大赛一等奖）：无公开仓库（仅存于官方新闻与赛事平台提交），但其披露的五层体系"数据接入 → 统一规格 → 工具链支撑 → 资源服务 → 输出生态"是评审认可的叙事框架——本方案 v1 覆盖前四层，第五层写入路线图。
- **NILMTK**（github.com/nilmtk/nilmtk，Apache-2.0，956⭐）：能耗域唯一直接对标的开源工具库。借鉴其 Building→Meter→Appliance 元数据分层；差异化论据：安装重、英文、HDF5 老旧、无质量层；策略为兼容导出（oed → NILMTK HDF5）而非替代。
- **Croissant**（github.com/mlcommons/croissant，Apache-2.0）：MLCommons 机器学习数据集元数据标准，HuggingFace/Kaggle 均支持。设计目标：`oed-schema` 作为 **Croissant 兼容的能耗领域扩展**，使统一后的数据集可被国际主流数据集平台直接发现与索引——长期发展的生态钩子。

## 4. 交付物明细（= 创新点清单）

1. **oed-schema 统一规格**：层次模型 Dataset→Site→Meter→Channel；显式时区/UTC、SI 单位标准化、采样率元数据、电器类型本体、质量标记词汇（MISSING/OUTLIER/DRIFT/GAP/UNIT_ANOMALY）、版本化与迁移策略；Parquet 主存储 + JSON sidecar，兼容导出 NILMTK HDF5。
2. **转换器集（7 个数据源）**：REDD / UK-DALE / REFIT / ECO / IDEAL / Low Carbon London / 自有能耗数据集（首个原生格式数据集）；每个转换器自动产出数据血缘与许可证声明；附《贡献一个新数据集》模板指南。
3. **LLM 智能评注管线**：两段式——确定性扫描引擎（缺口、零值、饱和、采样抖动、时区错位）+ LLM 规则生成（输入 schema 与统计特征，输出 YAML 规则 → 执行引擎 → 自然语言解释的质量报告卡）；**规则经人工确认后沉淀为可复用规则库**（人机协同治理叙事）。
4. **基准评测**：Task1 聚合负荷预测（naive/seasonal/lightGBM 等基线）+ Task2 NILM 分解（2-3 个代表算法）；统一切分与指标（MAE/NDE），一张可复现排行榜；自有数据集上复用升级你已有的 sklearn 基线。
5. **中文文档与教程**：30 分钟上手教程、领域综述（各数据集横向对比表）、贡献指南。

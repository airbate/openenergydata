# 商业叙事与落地方向

> 本文档回答三个问题：这个项目在讲一个什么故事？谁会为它付钱？未来 6-18 个月从哪里落地？
> 所有市场事实均来自公开报道（来源见文末），所有产品能力均以仓库内证据为准，不预支未发生的功能。

## 一、叙事逻辑链（讲给不同人听的同一件事）

**核心叙事（一句话）**：
> AI 时代的数据是燃料，但没人验过燃料的纯度——OpenEnergyData 是能源数据的"尽调工具"：在建模、交易、发布之前，用可复核的证据链回答"这份数据可信吗"。

**叙事逻辑链**（每一环都有仓库内证据支撑）：

| 环节 | 陈述 | 证据 |
|---|---|---|
| 问题 | 公开/交易中的能源数据存在静默缺陷：截断、户号身份不明、单位错标，用错了的代价是整个模型/结论作废 | `cases/` 三个真实案例；10,781 个通道的单位描述冲突记录 |
| 麻木 | 数据发布方不自知、使用方不检查——因为检查工具缺位 | LCL 清洗版在 HF 被下载数百次，无人发现归一化与时间错位 |
| 解法 | 只读、带证据链、可复核的领域化检查（不是通用数据质量工具的参数调优） | `oed check` / `cases/index.html` |
| 自证 | 工具的第一个客户是我们自己：在旗舰数据集上发现并纠正了错误，撤回机制全程留痕 | `LCL-SOURCE-RECOVERY.md`、`runs/evidence/lcl-2012-correction/` |
| 愿景 | 从检查工具到能源数据的可信性标准（发布前质检 + 交易前尽调的事实规范） | 路线图见本文档第五节 |

**给不同受众的一句话**：
- 对研究者：*"在你把三个月训练时间押在一份数据上之前，花三分钟验一下它。"*
- 对企业数据团队：*"数据要素入场交易要尽调，财务报表要审计——你的能源数据凭什么免检？"*
- 对数据发布方：*"发布前跑一遍 oed check，别让你的用户成为你的 QA。"*

## 二、旗舰故事（所有对外材料的骨架）

2026 年 10 月，我们接入一份被广泛下载的伦敦智能电表清洗数据集（5,552 户 / 6,000 万行）。
自己的检查管线随后发现三层问题，层层递进：

1. **单位撒谎**：所谓 kWh 列实为全局 MinMax 归一化值（范围 0~9.71），无量纲；
2. **时间错位**：同一段读数序列在清洗版与官方原始数据中相差 3 小时——5,989 万可比对值中 5,910 万不符；
3. **身份黑箱**：户号被 LabelEncoder 编码成整数，原始映射未公开。我们用读数序列指纹+编码规则锚点，以三级证据强度重建了 5,552 户映射（5,524 户有连续读数硬证据）。

结果不是一篇"我们发现了 bug"的帖子，而是：**官方 168 个分区全量恢复（1.53 亿条真实记录）+ 分级证据的户号映射 + 正式撤回报告 + 全程可复核的审计文件**。
这个故事证明的不是"我们有个工具"，而是"这类错误真实存在、规模巨大、没有工具就会畅通无阻地流入你的模型"。

## 三、谁付钱：五类客户与付费场景

| 客户 | 痛点 | 付费场景 | 对应能力 |
|---|---|---|---|
| ① 能源 AI 研究者/高校实验室 | 用公开数据集发论文/做基线，数据错了论文作废 | 开源自用（社区口碑基本盘）；实验室版批量检查 | `oed check`、案例手册 |
| ② 企业数据科学团队（电网/综合能源/虚拟电厂/充电运营商） | 外部购入或合作交换的用电数据无法验证 | **数据引入即检查**的 CI 集成（私有化部署） | 批量 check + 证据 JSON + 退出码协议 |
| ③ 数据要素市场交易方 | 国家数据局推进数据资产化，入场交易需要质量与合规尽调 | **按次数据尽调报告**（随交易附带的第三方检查报告） | 质量报告卡 + 血缘/哈希回执 + 撤回审计 |
| ④ 数据发布方（政府数据开放平台、ModelScope/HF 发布者、竞赛主办方） | 发布缺陷数据集损害平台声誉（LCL 即为例证） | **发布前质检管道**（上线前跑 check，徽章随数据集展示） | CI 集成 + 检查徽章 |
| ⑤ 投资机构 / 采购方 | AI 能源赛道尽调时无法评估标的方数据资产真实质量 | **技术尽调服务**（用 oed 出具数据资产体检） | 全套证据链输出 |

**定价直觉**：① 免费（获客与信任）；② 按节点订阅；③④ 按次报告（数据交易额的零头即是工具费）；⑤ 项目制。开源核心保证信任，商业版卖"规模化 + 责任背书"。

## 四、为什么是现在（市场时机）

1. **数据要素×进入执行年**：国家数据局"数据要素×"大赛已办至多届，典型案例集公开发布；全国高质量数据集与数据标注供需对接大会现场成交 9 亿元——**数据作为资产被交易，就必然需要第三方质量尽调**，这是财税审计在资本市场扮演过的角色。
2. **AI+数据治理成为共识**：行业趋势报告一致指向"LLM 自动生成质量规则、智能分类分级"，但通用工具（Great Expectations / Soda / Monte Carlo）不懂能源领域语义——单位制、户号身份、表计截断特征恰恰是能源数据的痛点本体。领域化 + 证据链是真空位。
3. **能源数据规模爆炸**：智能电表、充电桩、分布式光伏数据体量指数增长，"先建模后验数"的隐性成本第一次超过"先验数"的成本。

## 五、落地路线（6-18 个月）

**近期（0-3 月）——建立可信度**
- 本仓库：案例网页 + 检查徽章样例发布；向 2-3 个被广泛使用的公开能源数据集作者提交 check 报告（LCL 恢复报告即首份）；
- 冲刺"第四届开放原子大赛"赛道一（评审权重与本项目证据链叙事高度对齐：技术创新=领域检查器，场景落地=数据要素×，开源治理=证据链全开源，长期发展=标准路线）；
- 发布 `oed-spec` 检查规范 v0（三项检查的 JSON Schema 化），邀请社区评审。

**中期（3-9 月）——插入既有管道**
- CI 集成形态（GitHub Action / 预提交钩子）+ 检查徽章（类似 CII Best Practices badge）；
- 谈 1-2 个数据发布平台（地方数据开放平台、ModelScope 数据集页）试点"发布前检查"；
- 面向数据交易所/拍卖机构的尽调报告模板与首个付费试点。

**长期（9-18 月）——从工具到标准**
- 推动"能源数据可信性检查规范"进入开源基金会孵化（开放原子有既有多元 AI 数据赛道先例）；
- 检查项扩展：时区与户号映射外部证据、覆盖完整性、跨源一致性（路线图已在 README 声明的"未验证"清单中列明）；
- 商业版：私有化批量检查 + 尽调报告 SaaS。

## 六、竞争与护城河

| 对手 | 它做什么 | 我们的差异 |
|---|---|---|
| Great Expectations / Soda / dbt tests | 通用表格数据质量规则 | 它们不认识"户号身份""表计截断特征""kWh 与 W"——领域检查项是我们的原创增量，且有真实战果 |
| Monte Carlo（商业数据可观测） | 云端数据可观测平台 | 面向数仓运维告警，不做"数据来源可信性尽调"，更不开源证据链 |
| NILMTK 等领域工具 | 能耗数据的加载与建模 | 互补：它们是"用数据"，我们是"验数据"；检查结论供它们消费 |
| 人工咨询/审计 | 第三方数据评估报告 | 人工贵、不可复跑；我们每一项检查可一键复现（69 项测试 + 案例复现脚本） |

**护城河本质**：证据链方法论（区分观察/推断/未知、撤回留痕、分级证据）+ 领域检查项的持续积累 + "自己先被抓"的公信力故事。

## 七、诚实边界（叙事的一部分）

- 当前验证范围明确声明在 README「支持范围与限制」：不验证源测量准确性、原始单位声明真实性、完整覆盖、时区与户号映射的外部真值；
- 商业叙事中不使用未实测的数字；所有对外表述以 `cases/` 与 `runs/` 证据文件为准；
- 撤回是产品能力而非丑闻：`withdrawn-*` 系列文件是我们主动留下的复核通道。

## 我们把全球最大的公开智能电表数据集之一，变成了一条命令的事

**OpenEnergyData（oed）**：一个 Apache-2.0 开源的能耗时序数据基座，今天宣布完成对 **Low Carbon London（LCL）** 数据集的完整接入——**5,567 个伦敦家庭、2011-2014 年、超过 1.1 亿条半小时用电读数**，这是全球最大的公开智能电表数据集之一。

### 做能源 AI 的人，都经历过这种痛

你决定用公开数据训练一个负荷预测模型，然后发现：

- REDD 是没有表头的纯文本，想知道哪列是冰箱得去翻论文；
- UK-DALE 每户一个文件夹，时区藏在文档第 3 页；
- LCL 是 110 个 CSV 拼起来的 10GB 文本，光解析就要一小时；
- REFIT 的功率单位是 kW，别人家是 W，还有人没写单位；
- 每换一个数据集，就要重写一遍解析、对时、清洗代码。

**这不是数据科学的活，这是数据泥瓦匠的活。** 而 oed 把这些泥瓦匠工作变成了一条命令：

```bash
oed convert lcl lcl_data/ out/   # 1.1 亿读数 → 统一 Parquet + 元数据清单
oed scan out/                    # 自动质量体检：缺口/越界/置零伪影/单位错误
oed report out/                  # 一张中文 HTML 质量报告卡
oed bench out/                   # 负荷预测基线排行榜
```

### 它不只是格式转换

**① 标准先行**：`oed-schema` 是兼容 MLCommons **Croissant** 标准的领域扩展——转换后的数据集能被 HuggingFace、Kaggle 等平台直接索引，而不是又一个私有格式。

**② 会抓真问题的质量引擎**：上线当天，扫描器就在一份已发表的 REDD 衍生数据集里发现了未披露的数据伪影——白天时段总表被批量置零 6-12 小时（光伏注入实验的痕迹），105 处，全部带精确时间戳。用这份有问题的数据训练模型？你的模型会学会"中午不用电"。

**③ 大模型参与的规则治理**：启发式家电常识库 + 任意 OpenAI 兼容大模型（含本地部署）自动生成领域质量规则，但**每条规则必须人工确认才能生效**，审核人署名全程留痕。AI 提效，人负责。

**④ 可复现基准**：统一格式的直接红利——同一套代码在所有数据集上跑负荷预测与 NILM 基线。接入 LCL 后我们跑出的第一组真实数字：日常作息画像基线（daily_profile）把朴素预测的 MAE 砍掉一半以上。

### 为什么是现在

2026 年，时序基础模型（Chronos / TimesFM / TimeGPT）正在把负荷预测变成"零样本"任务，电力行业的大模型应用井喷。但基础模型需要干净、统一、可索引的数据——**能源领域恰恰最缺这一层**。oed 补的就是这层：让研究者把时间花在模型上，而不是泥瓦匠上。

## 我们用自己的工具，抓了一份公开数据集的"三重谎言"——然后决定把它开源

2026 年 10 月，我们准备用一份被广泛下载的伦敦智能电表数据集（Low Carbon London 清洗版，5,552 户、6,000 万行）训练负荷预测模型。数据下载下来，跑通管线，一切正常——直到我们按流程对它做了一次"数据尽调"。

然后我们发现了三件事，每一件都足以让基于它的研究作废：

**第一，单位在撒谎。** 数据集声称的 kWh 用电量列，实际是作者做过全局 MinMax 归一化的数值——取值范围 0 到 9.71，无量纲。任何把它当千瓦时用的模型，学到的是一个不存在的物理世界。

**第二，时间是错的。** 我们用读数序列指纹把清洗版和官方原始数据对齐：同一 households 的同一段读数，时间相差 3 小时。5,989 万个可比对值中，5,910 万个在归一化后仍不一致。如果你的应用关心"几点用电"——比如光伏消纳、分时电价——这份时间就是毒药。

**第三，身份是黑箱。** 户号被 LabelEncoder 编码成整数，映射字典没有公开。你根本不知道两次出现的"用户 37"是不是同一个人。

### 关键在于：这些错误畅通无阻

这份清洗版在 Hugging Face 上被下载了数百次。没有人发现——不是因为大家不专业，而是因为**没有工具做这件事**。通用数据质量工具（Great Expectations 之类）会告诉你"没有空值、类型正确、主键唯一"——全是真的，也全都没用：数值在合法范围内，只是不是它声称的物理量。

所以我们在三个通宵里做了三件事：从 London Datastore 恢复了官方全部 168 个分区、1.53 亿条真实记录（逐文件与上游哈希核对，168/168 通过）；用读数序列指纹+编码规则锚点，以三级证据强度重建了 5,552 户的身份映射（其中 5,524 户有连续读数硬证据）；然后把这份调查变成一个开源工具。

### 它叫 OpenEnergyData（oed）：能源数据的"尽调"工具

```bash
oed check source1.feather source2.feather -o checks/   # 结构、身份表示、单位声明
oed check --dataset my-dataset -o checks/dataset        # OED 清单 + 全量 Parquet 内容
```

- **只读**：绝不修改你的输入数据；
- **证据链**：每个结论区分"观察到 / 推断出 / 未知"，附 SHA-256 与样本，可独立复核；
- **会撤回**：我们自己曾基于坏数据生成过物理基准，发现后原路径改为撤回说明，修改前证据全部留档——撤回是能力，不是丑闻；
- **领域化**：文件截断特征、户号身份表示、能量/功率单位声明——这些是通用工具永远学不会的能源语义。

69 项测试全绿，GitHub Actions 双版本 CI，Apache-2.0，最小案例合成样本复现、无需下载任何大数据。

### 为什么值得你花三分钟装它

如果你用公开能源数据训练模型、写论文、做数据交易决策——这份工具的价值不是"帮你还行"，是"**在你把三个月押上去之前，告诉你数据配不配**"。我们已经用它抓了自己一次：那 6,000 万行静默失真的数据，本来会安静地流进我们的模型。

商业与落地层面：数据要素市场入场交易需要质量尽调，数据发布方需要上线前质检，企业引入外部能源数据需要引入即检查——[商业叙事与落地方向](docs/商业叙事与落地.md)里我们把这五类客户、三条落地路线写清楚了。

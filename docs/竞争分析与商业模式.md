# 竞争分析与商业模式调研

> 调研日期：2026-10-17。覆盖：通用数据质量/可观测、数据集信任、Agent 数据接口、能源域数据平台。
> 所有关键事实附来源链接；标注（背景知识）的为未经本轮搜索核实的既有认知。

## 一、市场分层与玩家地图

| 层 | 代表开源项目 | 代表商业产品 | 商业模式 |
|---|---|---|---|
| 数据质量测试（规则/Schema） | **GX Core**（Apache-2.0）、**Soda Core**、DQOps（OSS 受限）、Pandera | GX Cloud（已关停）、Soda Cloud | Open-core + SaaS 订阅 |
| 数据可观测（监控/告警/事件） | **Elementary**（dbt 原生，dbt Hub 前 5 包）、DataHub（元数据目录） | Monte Carlo（纯商业，2022 年 D 轮估值 14 亿美元，背景知识）、Bigeye、Metaplane、Sifflet | Open-core + Cloud；或纯 SaaS |
| 数据中心 AI（ML 数据集问题检测） | **cleanlab**（Confident Learning，文本/图像/表格/音频） | Cleanlab Studio、Galileo（已转向 LLM 评测/可观测） | OSS 获客 → 企业平台 |
| 数据集信任/溯源标准 | **Croissant**（MLCommons 标准）、Data Cards/Datasheets（文档框架，非工具） | — | 标准无商业模式，平台（HF/Kaggle）间接变现 |
| **Agent 数据接口（MCP）** | DataHub MCP Server、各类数据库 MCP Server | **Precisely MCP Server for Data Integrity**（"让 agent 安全访问可信数据"）、dbt MCP 指南、Informatica | 随企业数据套件捆绑（起步期） |
| 能源数据平台 | NILMTK（研究）、Pecan Street（研究型非营利） | **Arcadia（Arc）**：公用事业数据聚合 API，2022 年 E 轮 2 亿美元；UtilityAPI、Bayou Energy | B2B API 订阅/按用量计费 |

## 二、关键玩家的商业逻辑拆解

### GX (Great Expectations) —— Open-core 的兴衰样本
- 路径：Apache-2.0 OSS 框架成为行业事实标准 → 推出 GX Cloud（SaaS）→ 被 **FICO 收购** → **GX Cloud 于 2026-06-01 关停**（客户约 30 天迁移期），开源项目交由 **Fivetran 托管**。
- 来源：[DataKitchen 分析](https://datakitchen.io/blog/when-the-cloud-goes-dark-a-note-to-great-expectations-customers)、[Data Stack Index](https://datastackindex.com/data-observability/tools/great-expectations)
- **教训**：① open-core 的 SaaS 层在并购中最先被牺牲；② OSS 社区托管的连续性依赖中立第三方（Fivetran）；③ 原龙头云服务关停会腾出真实的市场空隙。

### Soda —— Open-core 订阅的标准打法
- Soda Core（OSS，YAML 声明式检查 CLI）+ Soda Cloud（可观测/异常/事件管理，AI 原生转型）。
- 累计融资约 **1.014 亿美元**（5 轮），2024-07 追加 1,400 万（Singular、Point Nine 领投）。
- 来源：[soda.io](https://soda.io)、[StartupIntros](https://startupintros.com/orgs/soda)
- **逻辑**：OSS 是获客漏斗与信任凭证，付费层卖"规模化（时间序列、漂移、事件流）+ 责任背书"。

### Elementary —— 生态嵌入型漏斗
- OSS CLI 深度绑定 dbt（dbt Package Hub 前 5）→ Cloud 版加告警/事件管理（报价制）。
- 来源：[elementary-data.com](https://www.elementary-data.com)、[OSS→Cloud 案例页](https://www.elementary-data.com/customer-stories/switching-from-elementary-open-source-to-elementary-cloud)
- **逻辑**：寄生在既有生态（dbt）的分发网络里，用户规模到复杂度阈值后自然溢出到付费层。

### cleanlab / Galileo —— 数据中心 AI 的 OSS→平台
- cleanlab：OSS 库（基于模型找标签错误/离群/近重复）→ Cleanlab Studio 企业平台；Galileo：CV 数据智能 → 转向 LLM 评测可观测。
- 来源：[cleanlab GitHub](https://github.com/cleanlab/cleanlab)、[Businesswire（Galileo 发布）](https://www.businesswire.com/news/home/20230503006119/en/)
- **逻辑**：基于模型（而非规则）的检查差异化，卖"自动发现人工发现不了的问题"。

### Precisely / DataHub / dbt —— Agent 数据信任（新战场，2026 年成形成本最低）
- Precisely 发布 **AI Agent & MCP Server for Data Integrity**，口号即"让 agent 安全地发现和访问可信数据"；DataHub 推出 MCP Server；dbt 发布"为 MCP 与 Agentic AI 准备数据"指南；安全侧出现 MCP 零信任模式（身份传播、schema 校验、审计）。
- 来源：[Precisely](https://www.precisely.com/press-release/precisely-advances-agentic-ready-data-with-a-new-ai-agent)、[DataHub MCP](https://datahub.com/resources/datahub-mcp-server-overview)、[dbt 博客](https://www.getdbt.com/blog/mcp-servers)、[TrueFoundry MCP 安全](https://www.truefoundry.com/blog/mcp-security)
- **逻辑**：把"可信数据"从数仓内部能力延伸为 **agent 可消费的接口**——正是"agent 成为数据消费者"范式的第一波商业化。注意：现有玩家全部绑定自家套件，**无中立检查器**。

### Arcadia (Arc) —— 能源数据聚合的付费验证
- 公用事业账单/Interval 数据聚合 API，B2B 订阅/用量计费，客户含 Johnson Controls 等企业；2022 年 E 轮 2 亿美元。
- 来源：[Crunchbase](https://news.crunchbase.com/business/arcadia-utility-data-api-climate-software-startup-venture)、[Johnson Controls 集成文档](https://docs.johnsoncontrols.com/bas/r/Johnson-Controls/en-US/OpenBlue-Enterprise-Manager-Product-Bulletin/4.7/Arcadia-Utility-Cloud-API-Integration)
- **逻辑**：能源数据的获取与标准化本身就值 2 亿美元融资——但它做的是"搬运与规整"，**不做可信性尽调**。

## 三、商业逻辑的规律总结

1. **Open-core + 订阅是本领域默认路径**（Soda/Elementary/GX 均如此）：OSS 负责"信任与分发"，付费层卖规模化能力（时序监控、事件管理、协作）。
2. **付费点始终是"责任与规模"而非"检查本身"**：检查逻辑几乎全部开源免费；收费的是告警、事件工作流、SLA、托管。
3. **退出通道成熟**：GX→FICO、Databand→IBM——该赛道是被企业软件巨头持续并购的领域。
4. **风险同样被验证**：GX Cloud 关停说明——没有护城河的 SaaS 层可能一夜消失；中立托管与社区是 OSS 的长期生命线。
5. **新战场（agent 数据信任）已开打但无中立者**：Precisely/DataHub/dbt 的 MCP 全是自家生态捆绑，"跨套件、领域化、证据链"的中立检查器不存在。

## 四、对 OpenEnergyData 的定位启示

**已被验证的付费意愿**：Soda 融资 1 亿美元、Monte Carlo 估值 14 亿、Arcadia 融资 2 亿美元——"数据可信/能源数据"两个要素各自都有资本背书，但**两者的交集（能源数据可信性尽调）无人占位**。

**oed 的三个差异化站位**（竞品均未覆盖）：
1. **领域语义检查项**：户号身份表示、能量/功率单位声明、表计截断特征——通用工具的规则引擎写不出这些；
2. **尽调级证据链**：区分观察/推断/未知、撤回留痕、分级证据——现有工具输出"通过/失败"，我们输出"可辩护的结论"（对数据交易尽调场景是刚需）；
3. **中立 Agent 检查协议**：`oed check` 的 JSON+退出码天然可包装为 MCP server，服务"agent 拿数前先验数"——不绑定任何数据套件，恰是 Precisely 们做不到的中立位。

**风险提示**：① 大厂（Informatica/Precisely/DataHub）正快速在 MCP 数据信任上布局，窗口期以月计；② 通用工具添加领域规则包的可能性存在（Soda 的检查配置可自定义），护城河必须建立在"领域知识库 + 调查案例公信力"上而非检查框架本身；③ 参照 GX 教训，未来若做商业层，托管与社区中立性要在架构期就设计进去。

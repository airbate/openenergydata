# 目标用户与核心问题

> 定位配套文档：与《商业叙事与落地》《竞争分析与商业模式》互链。
> 一句话：**谁在数据上做重大决定，谁就是我们的用户；决定越大、发现越晚，付账越痛快。**

## 一、核心问题

**本质**：AI 让数据消费量爆炸式增长，但"验证数据可信"仍是手工作坊——错误数据静默流入模型、论文和交易，代价在几周后才爆炸，而那时没人记得去查数据。

三个具体核心问题（即产品三大检查域，均有真实战例）：

| 核心问题 | 通俗版 | 已验证战例 |
|---|---|---|
| ① 数据真的完整吗？ | 截断、缺口、采集中断——你以为是全量，其实是残卷 | LCL 恢复 2,042 处缺口 |
| ② 这些实体是同一回事吗？ | 户号编码、跨文件 ID 对不上 | 5,552 户分级证据身份重建 |
| ③ 声明和实际相符吗？ | 说是 kWh 其实是归一化值 | LCL 6,000 万行静默归一化 + 时间错位（59M 值审计） |

**根源问题（商业支点）**：以上验证今天全靠人工 + 信誉——发布方说"这数据很好"，下载方就信了。数据行业的信任靠口碑流转，而金融、食品、外贸早就用"第三方可复核检验"替代了口碑。oed 卖的是这个替代。

## 二、目标用户（按疼的程度 × 付费能力排序）

| 优先级 | 用户 | 触发时刻 | 付费能力 | 策略 |
|---|---|---|---|---|
| P0 滩头 | 用公开数据集的 AI 研究者/工程师 | 下载 6GB 数据开训之前；审稿人要求数据合规证明 | 低（免费开源） | 获客 + 口碑 + 引用 |
| P1 付费主力 | 企业数据团队（电网/综合能源/金融/制造） | 外部数据接入数仓之前，"数据引入即检查"进 CI | 高（私有化 + 订阅） | 核心营收 |
| P1 付费主力 | 数据发布方与平台（ModelScope/HF/政府开放平台/竞赛主办方） | 数据集上线前——别让用户当你的 QA | 中高（发布前质检管道） | 对标 CQC"以评促建" |
| P2 高客单 | 数据要素交易买方与交易所 | 数据资产交易尽调（对标 DCMM 12-50 万/次行情） | 按次尽调报告 | 第三方报告服务 |
| P2 战略 | AI Agent 平台与工具链 | agent 自主取数之前（agent 是不设防的数据消费者） | 未来（MCP 协议位） | `oed check` 退出码协议 |
| 滩头协同 | 期刊/会议与大学研究诚信办 | NeurIPS D&B 投稿、Scientific Data 技术审评、撤稿调查 | 资助/声誉驱动 | cleanlab 路径 |

## 三、产品名与一句话

**数鉴 DataProof** —— 给 AI 时代的数据做的"尽调引擎"：在任何人用这份数据训练模型、写论文或做交易之前，一条命令验证它的完整性、身份与单位声明，每条结论附带可复核的证据链；我们的第一个战果，是抓出了一份被广泛使用的 6,000 万行公开数据集的静默造假。
